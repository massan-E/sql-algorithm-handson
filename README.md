# SQL × アルゴリズム ハンズオン

同じ結果を返すコードでも、書き方しだいで実行時間は何十倍、何千倍と変わります。
このハンズオンでは、遅い書き方を実際に測り、自分で書き直して、また測る、を繰り返します。

ActiveRecord や AI が書いてくれるコードを「なんか遅そう」と感じて、確かめて、直せるようになることがゴールです。

## 必要なもの

- Docker Desktop（起動しておいてください。Settings > Resources の Memory は 4GB 以上）
- git

Ruby や MySQL を自分の PC に入れる必要はありません。すべて Docker の中で動きます。

## セットアップ

```bash
git clone <このリポジトリのURL>
cd sql-algorithm-handson
./setup.sh
```

「セットアップが完了しました！」と出れば準備完了です。初回は Docker イメージのダウンロードがあるので数分かかります。

## 使い方

お題は `exercises/` にあります。各お題のフォルダの `README.md` に内容が書いてあります。

| お題 | 内容 |
|---|---|
| 00 | 1〜n の合計を求める |
| 01 | 掲示板についた未読コメントの数を数える |
| 02 | 掲示板についたコメントからランダムに1件取り出す |
| 03 | 【追加問題】掲示板ごとのコメント数を数える |
| 04 | 【追加問題】ユーザーが掲示板にコメントしたことがあるか調べる |

### 1. まず遅い書き方を測る

```bash
bin/run 02
```

`baseline`（配布した遅い書き方）の実行時間と、発行されたSQLの回数が表示されます。
`bin/run 02 --sql` にすると、発行されたSQLの中身も見られます。

### 2. 自分で書いてみる

```bash
bin/try 02
```

`my_code/02_random_comment/01.rb` ができます。中身は baseline のコピーなので、`solve` メソッドを書き換えてください。
ファイルの先頭に「仮説」と「結果メモ」を書く欄があります。どう考えてその書き方にしたのかも残しておきましょう。

### 3. 測る

```bash
bin/run 02
```

baseline と、自分が書いたファイルが全部並んで表示されます。

```text
名前                    実行時間        最遅   SQL回数   baseline比    結果
---------------------------------------------------------------------------
baseline                  1.12 s      1.12 s         2         x1.0    OK
my 01.rb                245.1 µs      5.7 ms         1       x4,555    NG
my 02.rb                141.5 ms    905.2 ms         2         x7.9    NG

  my 01.rb: ランダム性: 10回実行して毎回同じコメントが返っています
  my 02.rb: コメント0件の掲示板1: ActiveRecord::RecordNotFound
```

結果が NG のものは、速くても答えが間違っています。理由が表の下に出るので、直してみてください。

### 4. もう一度書いてみる

```bash
bin/try 02
```

もう一度実行すると `02.rb` ができます。中身は直前の `01.rb` のコピーです。
**前のファイルは上書きされずに残る** ので、試した書き方の履歴がそのまま残ります。

### 自由に試したいとき

```bash
bin/console
```

`User` / `Board` / `Comment` が使える Ruby の対話環境が開きます。発行されたSQLと実行時間がログに出ます。

```ruby
Comment.where(board_id: 2).count
Comment.where(board_id: 2).select(:id).explain(:analyze)   # DB がどうやって探したかを見る
```

## 解答を見る

解説の時間になったら、次のコマンドで解答を取り出せます。

```bash
bin/answers
```

`answers/` フォルダに解答が入り、`bin/run` に解答も一緒に並ぶようになります。
今いるブランチも自分のコードもそのままなので、ファイルを編集した状態で実行しても大丈夫です。

ZIP でダウンロードした場合はこのコマンドが使えないので、GitHub 上でブランチを `answers` に切り替えて `answers/` フォルダを見てください。

## データ

| テーブル | 件数 |
|---|---|
| users | 300 |
| boards | 100 |
| comments | 1,000,000（うち掲示板2に100,000件、掲示板1は0件） |

もっと大きいデータで試したいときは、1000万件（うち掲示板2に100万件）でセットアップし直せます。

```bash
SCALE=10m ./setup.sh
```

データ作成に約1分、遅い書き方は1回の実行に10〜20秒かかります。
Docker Desktop の Settings > Resources で、Memory を 8GB 以上にしておいてください。
1000万件で遊び終わったら、`./setup.sh` で100万件に戻せます。

## 困ったとき

| 症状 | 対処 |
|---|---|
| `Docker が起動していません` と出る | Docker Desktop を起動してから `./setup.sh` をやり直す |
| `bin/run` で `service "app" is not running` と出る | `./setup.sh` をやり直す（データも作り直されます） |
| PC の動きが重い | 終わったら `docker compose stop` でコンテナを止める |
| 全部消してやり直したい | `docker compose down -v` のあと `./setup.sh` |
